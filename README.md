**1. [Lunar Seeker : Bound!] - 2D 액션 플랫포머 완성작 프로젝트**
* Godot Engine을 사용하여 개발한 2D 액션 플랫포머 게임입니다. 1인 개발 및 실제 출시 후 유지보수를 진행하였으며, 전투 시스템, 저장 시스템, JSON 기반 대화 시스템 등을 직접 구현했습니다.
  
* OOP 및 클린 코드 : 깊은 상속의 한계를 극복하기 위해 **컴포넌트 기반 설계**를 도입하여 확장성을 높이고 객체 간 결합도를 최소화함.
사용자 경험 최적화 : 물리 프레임 저하 및 조작 불쾌감을 방지하기 위해 코요테 타임, 선입력 버퍼, 모서리 보정 등 정교한 수학적 보정 알고리즘을 수식으로 구현함.
아키텍처 설계 : Singleton(Autoload)과 시그널 패턴을 융합하여 데이터 영역과 UI 영역을 분리, 1만 줄 이상의 프로젝트에서도 유지보수 비용을 획기적으로 낮춤.

**5. 핵심 기술 구현 사항**
   5-1. FSM 기반의 정교한 플레이어 컨트롤
   
      플레이어의 움직임과 액션이 FSM 패턴으로 철저하게 관리되고 있습니다.
      
      플레이어의 플랫포머 조작감 보정을 위해 넣은 것들
      
      * 코요테 타임 : 절벽에서 살짝 떨어져도 점프가 가능하도록 유예 시간을 줍니다.
      
      * 선입력 : 바닥에 닿기 직전에 점프를 누르면 착지하자마자 바로 점프가 나갑니다.
      
      * 가감속/마찰력 : acceleration과 friction 변수를 통해 멈추고 가속하는 것을 자연스럽게 도와줍니다.
      
      * 모서리 보정 : 점프 상승 중 머리 위쪽 모서리에 걸렸을 때 캐릭터를 살짝 옆으로 
      밀어주어 매끄럽게 올라가게 돕습니다.
      
      * 스쿼시 앤 스트레치 : 점프나 착지 시 캐릭터 스프라이트가 길쭉해지거나 찌그러지는 
      시각적 탄력성을 tween 기능으로 구현했습니다.

   5-2.  패링 및 퍼펙트 가드 전투 시스템
         액션성이 강조된 전투 시스템.
         
         * CombatBody2D: 체력, 무적 시간, 깜빡임, 넉백 저항 및 쿨타임 등을 처리하는 범용 전투 베이스 클래스를 만들어 
         플레이어와 적이 상속받도록 설계했습니다. 피격 시 파티클 스파크 생성과 피격 효과가 공통 적용됩니다.
         
         * 퍼펙트 가드 : 플레이어가 가드(GUARD 상태)를 올린 직후 아주 짧은 시간 안에 
         투사체를 막아내면 데미지를 무효화하고 퍼펙트 가드 보너스를 얻습니다.
         
         * 히트스탑 : 타격감 극대화를 위해 패링 성공, 공격 성공, 퍼펙트 가드 성공 시 GameManager.apply_hitstop을 호출하여
         게임의 Engine.time_scale을 아주 잠깐 느리게 만들어 좋은 타격감을 연출합니다.

   5-3. 글로벌 상태 및 게임 매니저
        * 싱글톤(Autoload) 패턴을 활용하여 게임의 전역 상태를 통제함.
        
        * 데이터 관리 : 체력, 돈, 인벤토리 배열, 잡은 보스와 몬스터 목록, 상호작용한 
        NPC들의 대화 내역 등을 메모리에 들고 있습니다.
        
        * 시그널 기반 UI 동기화 : 값이 바뀔 때마다 UI를 직접 조작하는 대신 시그널을 
        발사하여 UI 씬들이 독립적으로 업데이트 됩니다.
        
        * 세이브 연동 : 현재 상태를 사전 형태로 직렬화하여 SaveManager에 넘기고, 부활 시 
        마지막으로 저장한 체크포인트 위치와 씬으로 자동 이동시키는 부활/리스폰 로직을 담당합니다.

  5-4.  JSON 연동 대화 및 선택지 시스템
  
        하드코딩된 대화가 아니라 외부 JSON 파일을 읽어와 파싱하는 확장성 높은 대화 시스템입니다.
        
        * 포트레이트 연출: 왼쪽, 오른쪽 초상화를 띄우고 현재 말하는 화자를 강조하기 위해 말하지 않는 쪽은 어둡게, 
        말하는 쪽은 밝게 만들면서 약간 위로 통통 튀어오르는 트윈 애니메이션을 구현했습니다.
        
        * 조건부 선택지: 대화 중 분기가 발생할 수 있으며, GameManager의 정보(돈이 충분한가?, 특정 아이템이 있는가?, 
        보스를 잡았는가?)를 참조하여 condition을 체크하고 조건이 안 맞으면 선택지 버튼을 비활성화합니다.
        
  5-5.  리소스(Resource) 기반 아이템 구조 (ItemData.gd)
  
        * 아이템 정보를 노드나 스크립트 딕셔너리가 아닌 고도의 Resource 클래스로 분리하여 관리합니다.
        
        * ItemData라는 커스텀 리소스를 정의하여 에디터 인스펙터에서 아이템 아이콘, 이름, 설명, 가격 등을 
        쉽게 생성할 수 있게 만들었습니다.
        * 아이템 타입(소모품, 장비 등)에 따라 match 문으로 내부 로직을 분기하여, 체력을 회복하거나 최대 
        공격력/패링 배율을 영구적으로 올려주는 기능을 캡슐화해 두었습니다.

   
6. **트러블 슈팅 히스토리**
   
 I. 몬스터 지형 인식 예외 및 플랫폼 이탈 이슈
   
* 문제 상황 : 순찰 상태의 몬스터 엔티티가 특정 플랫폼 끝단 또는 위험 블록 구역을 감지하지 못하고 낙하하는 현상 발생.
* 원인 분석 : 기존 단일 다운워드 레이캐스트 방식은 충돌 레이어 검사 범위가 넓어 일반 플랫폼과 데미지 유발 블록(가시 등)의 속성을 정밀하게 분별하지 못함. 이로 인해 위험 구역을 안전한 지형으로 오인하여 낙하하게 됨.
* 해결 방안 : * Raycast의 감지 범위를 해당 엔티티의 이동 속도에 맞춰 최적화 및 축소.
* 지형 충돌 시 해당 레이어의 메타데이터(또는 데미지 컴포넌트 보유 여부)를 실시간 검사하여 위험 지형 감지 시 즉시 이동 방향 벡터를 반전시키는 예외 처리 로직 반영.
* 발전 방향 : 향후 세로 1칸 이하의 좁은 지형에서의 물리 관성으로 인한 이탈을 완벽히 제어하기 위해, 엔티티에게 추가적인 조치 예정.

 II. JSON 직렬화/역직렬화 데이터 무결성 오류
   
* 문제 상황 : 게임 세이브 및 로드 시스템 반복 수행 시, 저장 파일 파싱 실패로 인한 런타임 크래시 및 데이터 누수 발생.
* 원인 분석 : 수동 문자열 결합/파싱 과정에서 컴파일러가 잡아내지 못하는 원시 텍스트적인 오타가 발생. 런타임에 데이터 타입 미일치가 발생하여 직렬화 무결성이 깨짐.
* 해결 방안 : 데이터 테이블 전체를 1:1 검증하여 문법적 결함을 수정하고, 고도 엔진의 정석적인 JSON 파싱 API 문법으로 래핑하여 데이터 직렬화 로직의 안정성 확보.

 III. Autoload 레이스 컨디션으로 인한 UI 초기화 실패 이슈
   
* 문제 상황 : 미니맵 및 인벤토리 등 핵심 HUD UI 생성 시, 입력 이벤트(클릭 등)가 소실되거나 컴포넌트가 정상적으로 렌더링되지 않는 간헐적 에러 발생.
* 원인 분석: 전역 매니저 시스템 내 싱글톤 노드들의 로드 순서의 불명확성으로 인한 버그 발생. UI 씬이 로드되는 시점에 해당 UI가 참조해야 할 싱글톤 데이터 매니저가 메모리에 아직 할당되지 않아 널 포인터 계열의 예외가 유발.
* 해결 방안 : 고도 프로젝트 설정 내 Autoload 우선순위 및 실행 순서를 정렬하여 데이터 매니저가 상시 최우선 초기화되도록 종속성의 순서를 제어.
* 인벤토리 인덱스 매핑 로직의 무결성을 점검하고, 데이터 변경 시 UI가 이를 안전하게 구독하는 시그널 기반 비동기 업데이트 구조를 강화하여 해결.
